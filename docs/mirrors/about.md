# میرورهای نوین کلاود

`mirror.novin.cloud` یک آینه (mirror) از مخزن‌های عمومی نرم‌افزار است که داخل ایران میزبانی می‌شود.
به‌جای دریافت پکیج‌ها از سرورهای خارجی، آن‌ها را با سرعت داخلی و بدون درگیر شدن با تحریم دریافت می‌کنید.

## چرا از میرور استفاده کنیم؟

- **بدون تحریم** — بسیاری از مخزن‌های اصلی از ایران در دسترس نیستند. میرور این مشکل را حذف می‌کند.
- **سرعت داخلی** — ترافیک از داخل کشور سرو می‌شود، نه از آن‌سوی مرز.
- **بدون تحریم‌شکن** — نیازی به پراکسی یا VPN برای نصب پکیج نیست.
- **پایداری در CI/CD** — بیلدهای شما به در دسترس بودن سرورهای خارجی وابسته نیست.

## استفاده نمی‌خواهد ثبت‌نام کند

میرور **عمومی و رایگان** است. برای دریافت پکیج نیازی به حساب کاربری، کلید API یا لاگین ندارید.

:::note[درباره‌ی Docker]
رجیستری داکر هم عمومی است و `docker pull` بدون لاگین کار می‌کند. اگر مسیر `/v2/` را
مستقیماً با `curl` صدا بزنید پاسخ `401` می‌بینید — این بخشی از فرایند استاندارد توکن
داکر است و خود `docker` آن را خودکار انجام می‌دهد. جزئیات در [Docker و OCI](./docker).
:::

## آدرس پایه

همه‌ی مخزن‌ها زیر یک دامنه سرو می‌شوند:

```
https://mirror.novin.cloud/<نام-مخزن>/<مسیر-فایل>
```

برای مثال فایل `Release` مربوط به اوبونتو ۲۴.۰۴:

```
https://mirror.novin.cloud/ubuntu/dists/noble/Release
```

هر دو شکل زیر معتبر است و نتیجه‌ی یکسان می‌دهد؛ شکل کوتاه برای خوانایی توصیه می‌شود:

```bash
# شکل کوتاه (توصیه‌شده)
https://mirror.novin.cloud/ubuntu/...

# شکل کامل — همان مقصد
https://mirror.novin.cloud/artifactory/ubuntu/...
```

## زیرساخت

میرور روی **JFrog Artifactory** اجرا می‌شود. این یعنی علاوه بر فایل‌های ساده،
هر اکوسیستم مسیر API اختصاصی خودش را دارد (مثلاً npm و PyPI) که در صفحه‌ی هر سرویس آمده است.

مخزن‌ها سه نوع‌اند و آنچه شما استفاده می‌کنید نوع **virtual** است:
یک آدرس واحد که پشت صحنه هم کش محلی و هم مخزن بالادستی را پوشش می‌دهد.
لازم نیست دنبال نام‌های `-local` یا `-remote` بگردید.

## وضعیت سرویس

اگر درخواستی خطای `502` گرفت، معمولاً مشکل موقتی سمت سرویس است و با تلاش مجدد برطرف می‌شود.
در صورت ادامه، از طریق [تیکت پشتیبانی](https://console.novin.cloud) اطلاع دهید.
