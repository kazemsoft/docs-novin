# عیب‌یابی مشکلات رایج DNS

## دامنه در وضعیت «در انتظار» مانده است

دامنه تا زمانی که نام‌سرورهای آن به نوین کلاود اشاره نکند، فعال نمی‌شود.

**بررسی کنید:**

۱. نام‌سرورها را در پنل ثبت‌کننده دامنه **جایگزین** کرده‌اید (نه اینکه به فهرست قبلی اضافه کرده باشید).
۲. هر دو نام‌سرور را وارد کرده‌اید، نه فقط یکی.
۳. مقادیر را دقیقاً از صفحه همان دامنه در کنسول کپی کرده‌اید.

**سپس:**

```bash
dig NS example.ir +short
```

اگر خروجی هنوز نام‌سرورهای قبلی را نشان می‌دهد، تغییر هنوز منتشر نشده — معمولاً تا ۲۴ ساعت و در موارد نادر تا ۴۸ ساعت زمان می‌برد. بعد از آن دکمه **«بررسی مجدد»** را در کنسول بزنید.

## رکورد را ساختم ولی اعمال نمی‌شود

**۱. صبر کنید تا کش منقضی شود.** اگر رکورد را ویرایش کرده‌اید، سرورهای DNS تا پایان `TTL` قبلی، همان پاسخ قدیمی را تحویل می‌دهند.

**۲. پاسخ واقعی را ببینید:**

```bash
dig A www.example.ir +short
```

برای اینکه کش میانی را دور بزنید و مستقیم از نام‌سرور بپرسید:

```bash
dig A www.example.ir @ns1.example-ns.ir
```

**۳. کش سیستم خودتان را پاک کنید:**

```bash
# macOS
sudo dscacheutil -flushcache

# Linux (systemd)
sudo systemd-resolve --flush-caches

# Windows
ipconfig /flushdns
```

## فرم، نام دامنه را نمی‌پذیرد

دامنه را بدون `http://`، بدون `www` و بدون اسلش پایانی وارد کنید — فقط `example.ir`.

برای **زیردامنه** (مثل `blog.example.ir`) دامنه اصلی را اضافه کنید و سپس زیردامنه را به‌صورت یک **رکورد** با نام `blog` داخل همان دامنه بسازید.

## رکورد CNAME روی دامنه اصلی ساخته نمی‌شود

این محدودیت استاندارد DNS است، نه محدودیت نوین کلاود. روی ریشه دامنه (`@`) نمی‌توان `CNAME` ساخت. به‌جای آن از رکورد `A` با آدرس IP مقصد استفاده کنید.

## ایمیل‌ها دریافت نمی‌شوند

- مطمئن شوید رکورد `MX` با نام `@` ساخته‌اید.
- مقدار `MX` باید به یک **نام دامنه** اشاره کند، نه به IP.
- رکورد `SPF` (از نوع `TXT`) را برای جلوگیری از اسپم‌شدن ایمیل‌های ارسالی تنظیم کنید.

## هنوز مشکل پابرجاست

از بخش [تیکت‌های پشتیبانی](https://console.novin.cloud/dashboard/tickets) تیکت ثبت کنید. برای بررسی سریع‌تر، خروجی دستور `dig` و نام دامنه را در تیکت بنویسید.
