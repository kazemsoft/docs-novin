# سرچشمه و لوکیشن

## سرچشمه (Upstream)

سرچشمه، سرور اصلی شماست که محتوا از آن خوانده می‌شود. از تب **«سرچشمه‌ها»** در صفحه گیت‌وی، سرور خود را معرفی کنید.

## لوکیشن (Location)

لوکیشن مشخص می‌کند کدام مسیر از آدرس سایت، به کدام سرچشمه برود. هنگام ساخت لوکیشن این فیلدها را پر می‌کنید:

| فیلد | توضیح |
|---|---|
| **نام** | نام لوکیشن |
| **سرچشمه** | یکی از سرچشمه‌های تعریف‌شده |
| **نوع مسیر** | `prefix` (شروع‌شونده با) یا `exact` (دقیقاً برابر) |
| **مسیر** | مثلاً `/` یا `/api` |

**مثال:**

```
مسیر /        →  سرچشمه وب‌سرور
مسیر /api     →  سرچشمه سرور API
```

## تنظیمات کش

تنظیمات کش، هنگام **ساخت لوکیشن** تعیین می‌شود:

| تنظیم | پیش‌فرض | توضیح |
|---|---|---|
| **سطح کش** | `standard` | `standard` کش فعال، `bypass` بدون کش |
| **TTL مرورگر** | ۳۶۰۰ ثانیه | مدت نگهداری در کش مرورگر کاربر |
| **TTL لبه** | ۳۶۰۰ ثانیه | مدت نگهداری در سرورهای نوین کلاود |
| **TTL پاسخ ناموفق** | ۳۶۰۰ ثانیه | مدت نگهداری پاسخ‌های خطا |
| **TTL کهنه** | ۳۶۰۰ ثانیه | مدت ارائه نسخه کهنه هنگام در دسترس نبودن سرچشمه |
| **کش تغییرناپذیر** | خاموش | برای فایل‌هایی که هرگز تغییر نمی‌کنند |

:::warning تنظیمات کش پس از ساخت قابل ویرایش نیست
در حال حاضر امکان ویرایش لوکیشن وجود ندارد. برای تغییر تنظیمات کش، باید لوکیشن را **حذف** و دوباره با مقادیر جدید **بسازید**.
:::

:::note پاک‌سازی کش (Purge)
امکان پاک‌سازی دستی کش از طریق کنسول هنوز در دسترس نیست. برای انتشار سریع تغییرات، می‌توانید هنگام ساخت لوکیشن مقدار **TTL لبه** را کمتر بگذارید، یا نام فایل‌های استاتیک را هنگام انتشار نسخه جدید تغییر دهید (مثلاً `app.v2.js`).
:::
